  <action>
Replace the stub implementation in `extension/components/dwell-tracker.ts` with full implementation.

**Implementation requirements:**

1. `startTracking(tabId, url, title)`:
   - Load `dwellTimestamps` from chrome.storage.local (D-06: persist to storage, not memory)
   - If an existing record for `tabId` exists, remove it (cancel previous tracking)
   - Create new DwellRecord: `{ url, title, tabId, startTime: Date.now() }`
   - Save to chrome.storage.local under key `dwellTimestamps` keyed by tabId (string)
   - Schedule `checkDwell(tabId)` after `DWELL_THRESHOLD_MS` (5000ms) using setTimeout
   - Note on setTimeout reliability: Per RESEARCH.md Pitfall 4, setTimeout is acceptable for <30s delays with ~5% failure rate. chrome.alarms API has a minimum 1-minute interval in Chrome stable, so it cannot be used for 5-second delays.

2. `cancelTracking(tabId)`:
   - Load `dwellTimestamps` from chrome.storage.local
   - Delete the entry for `tabId`
   - Save updated `dwellTimestamps` back to storage

3. `checkDwell(tabId)`:
   - Load `dwellTimestamps` from chrome.storage.local
   - If no record for `tabId`, return false
   - Calculate elapsed = Date.now() - record.startTime
   - If elapsed < DWELL_THRESHOLD_MS, clean up record and return false
   - If elapsed >= DWELL_THRESHOLD_MS:
     - Load blocklist via `loadBlocklist()`
     - Parse hostname from record.url using `new URL(record.url).hostname`
     - If `isBlocked(hostname, blocklist)`, clean up and return false
     - Otherwise, call `saveCapture({ url: record.url, title: record.title, domain: hostname, timestamp: record.startTime, source: 'live' })`
     - Clean up dwell record from storage
     - Return true

**Test implementation:**

Create a mock for `browser.storage.local` that uses an in-memory object. Use `vi.useFakeTimers()` to control `Date.now()` and `setTimeout` for deterministic dwell threshold testing. Write tests for each behavior listed above.

Replace the placeholder `extension/entrypoints/background.ts` with the full service worker implementation.

**CRITICAL MV3 REQUIREMENTS** (from RESEARCH.md Pitfall 1):
- All event listeners MUST be registered synchronously at the top level of the `defineBackground` callback
- Do NOT use `document`, `window`, or `chrome.runtime.getBackgroundPage()`
- Do NOT store state in module-level variables (service worker terminates after 30s idle)
- All state reads/writes go through chrome.storage.local

**Implementation:**

Inside `defineBackground()`, register all event listeners synchronously:
1. `browser.webNavigation.onCompleted.addListener(handlePageLoad)` -- start dwell tracking
2. `browser.tabs.onActivated.addListener(handleTabActivated)` -- D-13: track on focus
3. `browser.tabs.onRemoved.addListener(handleTabRemoved)` -- cancel pending dwell
4. `browser.runtime.onInstalled.addListener(handleInstall)` -- initialize defaults
5. `browser.runtime.onStartup.addListener(handleStartup)` -- D-02: reset pause

**Event handler implementations:**

`handlePageLoad`: Only process frameId===0 (main frame). Skip non-http URLs. Check isPaused from storage. Check blocklist. D-13: Check if tab is active tab in its window -- if not, skip (handleTabActivated will catch it on focus). Call startTracking for qualifying pages.

`handleTabActivated`: Get tab info, skip non-http, check isPaused, check blocklist, call startTracking.

`handleTabRemoved`: Call cancelTracking to clean up pending dwell records.

`handleInstall`: If reason==='install', load default blocklist from blocklist.json and save to storage.

`handleStartup`: D-02: Reset isPaused to false. Log startup.

**Export handler functions** for testing. Create `extension/tests/background.test.ts` with mocks for dwell-tracker, blocklist, and storage modules.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser events -> service worker | URL data from webNavigation/tabs events could be any URL including sensitive ones |
| chrome.storage reads | Stored state could be corrupted from previous sessions or extension bugs |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-05 | Information Disclosure | background.ts handlePageLoad | mitigate | Filter chrome://, about://, chrome-extension:// URLs before processing; check blocklist before capture |
| T-01-06 | Denial of Service | dwell-tracker.ts | mitigate | Clean up dwell records on tab close (handleTabRemoved) to prevent storage leak; limit dwell records to active tabs only |
| T-01-07 | Tampering | dwell-tracker.ts checkDwell | mitigate | Re-check blocklist at capture time (not just at startTracking) to prevent capture of URLs added to blocklist during dwell period |
| T-01-08 | Information Disclosure | background.ts | accept | Service worker console.log statements may expose captured URLs in DevTools -- acceptable for development, can be removed for production |
</threat_model>
